# 7月18日里程碑面试准备

这份文档只对应当前项目做到 `2026-07-18` 的版本，重点是帮助你快速理解这次补齐的监控预览、权限边界和线程收口。

## 容易出错的部分

### 1. 线程停止与资源释放
- `MonitorTask` 跑在独立线程里，停止时先置 `m_stopRequested=true`，再退出循环。
- 退出循环后必须依次处理：停止录像、释放 `VideoCapture`、发送“已停止”状态。
- 如果直接销毁线程对象但没有 `wait()`，容易出现退出时崩溃、摄像头句柄没释放、下一次启动失败。

### 2. 摄像头和文件源切换
- 通道 1 是真实摄像头，通道 2-4 是 `video/` 目录下的固定文件。
- 这意味着 `MonitorTask` 不能再只会 `open(cameraIndex)`，必须有输入源概念。
- 文件源和摄像头源的异常处理不同：
  - 摄像头打不开，要提示“摄像头打开失败”。
  - 文件不存在或打不开，要明确告诉是文件问题。

### 3. OpenCV / Qt 图像转换生命周期
- `cv::Mat` 的内存通常由 OpenCV 管理，不能直接把裸指针长期交给 UI。
- 当前实现里 `matToImage()` 最后用了 `.copy()`，这是为了让 `QImage` 拥有独立数据，避免线程切换后访问悬空内存。
- 这个点很容易被问到，因为它直接关系到崩溃和花屏问题。

### 4. UI 状态与任务状态不同步
- UI 线程只负责显示，采集线程只负责读帧和产出状态。
- `m_latestFrames` 只是“最后一帧的显示缓存”，不是跨线程同步队列。
- 如果把“是否正在预览”“当前画面是什么”“录像是否开启”混在一个状态变量里，很容易出现按钮文字和真实状态不一致。

### 5. 视频文件循环播放与异常恢复
- 文件源读到结尾时会返回空帧。
- 当前做法是检测到空帧后把 `CAP_PROP_POS_FRAMES` 置回 `0`，再继续读，实现循环播放。
- 如果重置后仍然读不到帧，线程会短暂 sleep 后继续尝试，而不是直接把程序打死。

### 6. 数据库不可用时的降级行为
- 当前项目的监控预览不应该依赖数据库。
- 即使 MySQL 没连上，监控画面也应该能跑；受影响的只是录像入库和回放列表。
- 这是“主功能可用、附属功能降级”的典型工程思路，面试时很好讲。

## 面试官重点追问的部分

### 1. 为什么采集放在线程里，而不是放在 UI 线程里
- 摄像头读取和视频解码都可能阻塞。
- 如果把 `VideoCapture >> frame` 放在 UI 线程，窗口刷新、按钮响应、布局切换都会卡住。
- 所以这里要把“采集”和“显示”拆开：采集在线程中做，显示通过信号槽交给 UI 线程。

### 2. 为什么采用“1路真实摄像头 + 3路演示视频”
- 这是针对 `2026-07-18` 里程碑的工程取舍。
- 目标是先把四通道预览的交互、布局、线程模型和状态链路跑通，而不是一开始就依赖 4 路真实硬件。
- 这样做的好处是：
  - 没有 4 个摄像头也能完整演示。
  - 先验证多通道 UI 和任务模型。
  - 后续扩展到真 4 路摄像头时，改的是输入源配置，不是整套页面逻辑。

### 3. 如果以后扩展到真正 4 路摄像头，接口怎么演进
- 当前 `MonitorTask` 已经支持“输入源配置”，不再绑定“通道号 = 摄像头号”。
- 后续只需要把通道配置从“固定写死”升级为“外部配置”或“设备探测结果”即可。
- 也就是说，扩展点在配置层，不在采集线程主逻辑。

### 4. QImage / Mat 拷贝与性能权衡
- 现在用了 `.copy()`，这是偏安全的做法。
- 好处是不会踩生命周期问题。
- 代价是每帧都会发生一次内存拷贝，帧率高时会增加 CPU 和内存带宽开销。
- 如果后续要做更高性能版本，可以再考虑零拷贝或对象池，但当前里程碑优先保证稳定。

### 5. 如何避免 stop / start 时的竞态
- 关键点是“一个任务对象只负责一个输入源的一次运行周期”。
- 停止时不直接粗暴销毁，而是：
  - 先发停止标志
  - 等线程退出
  - 再 delete
- 重新启动时重新创建任务对象，这样比在线程运行中动态改输入源更稳。

### 6. 当前方案的局限
- 目前没有真正的生产者-消费者队列，只有“线程采集 + 最新帧显示缓存”。
- 还没有做背压控制、掉帧策略、统一日志链路、真实多摄像头枚举。
- 回放页也只是基本列表，没有做复杂检索和播放器控制。

### 7. 如果进入 7月19日 之后，下一步该怎么升级
- 先补录像索引与回放控制，把“录制 -> 入库 -> 列表 -> 回放”链路做完整。
- 再引入真正的帧队列，把采集线程、显示线程、录像线程进一步解耦。
- 然后再上移动目标检测，让检测结果和录像状态联动。
- 到那一步，才值得认真做背压、延迟统计和性能优化。

## 你在面试里可以怎么概括这个版本

可以用一句话先讲清楚：

> 这个阶段我先把监控系统做到 7 月 18 日的里程碑版本，核心是把单/四通道预览、登录权限边界、真实摄像头与演示视频混合输入、以及线程安全的采集显示链路稳定跑通。

然后再往下展开三个关键词：
- 输入源抽象
- 采集线程与 UI 线程解耦
- 无硬件依赖的四通道演示方案

这样会比只讲“我做了一个监控项目”更容易抓住面试官注意力。
